## 1. 系统概览
PolyStudio 采用纯环境变量加 .env 文件的轻量级配置方案，未引入 pydantic-settings、dynaconf 等第三方配置框架。后端在应用启动时通过 python-dotenv 加载 .env，各模块直接通过 os.getenv() 读取；前端使用 Vite 构建时的 VITE_* 前缀变量（可选）。

## 2. 关键文件与位置
- backend/.env 和 backend/env.example：后端运行时配置清单（LLM 提供商、API Key、模型名、Mock 开关、日志级别等）
- frontend/env.example：前端可选的 VITE_API_BASE 和 VITE_STORAGE_BASE 示例
- backend/app/main.py：应用入口，调用 load_dotenv() 并读取 LOG_LEVEL
- backend/app/routers/settings.py：提供 /api/settings/env 和 /api/settings/workspace 两个运行时配置管理接口，支持在线查看和修改 .env 与工作空间 Markdown 文件
- backend/start.sh：启动脚本，检查 .env 是否存在后以 uvicorn 运行
- backend/app/llm/factory.py：根据 LLM_PROVIDER 动态选择火山引擎或 SiliconFlow LLM 实现

## 3. 架构与设计约定
- 单一配置文件：所有运行时参数集中在 backend/.env，按功能分组（LLM 提供商、图片生成、视频生成、3D 模型、TTS、ComfyUI、调试、日志），每个 key 都有中文注释说明。
- 默认值策略：os.getenv(key, default) 广泛使用，如 LLM_PROVIDER=volcano、LOG_LEVEL=INFO，保证无 .env 也能启动。
- 敏感字段标记：settings.py 中 ENV_GROUPS 列表为每个 key 标注 sensitive=True/False，/api/settings/env 返回给前端时用于脱敏展示。
- 运行时持久化：/api/settings/env 支持 PUT 更新 .env 中的已知 key，写入逻辑会覆盖已有行或追加到末尾，无需重启即可生效（但子进程需重新加载）。
- 工作空间配置：除 .env 外，workspace/ 目录下的 USER.md、SOUL.md、MEMORY.md、TOOLS.md、IDENTITY.md、AGENTS.md 作为可编辑的工作空间文档，由 workspace_service 维护并提供 REST 接口读写。
- 前端配置解耦：开发期通过 Vite proxy 转发 /api 和 /storage，通常不需要前端 .env；生产部署不同域名时才需要 VITE_API_BASE 等变量。

## 4. 开发者应遵循的规则
1. 新增配置项：先在 backend/env.example 添加带注释的 key-value 示例，再在 backend/app/routers/settings.py 的 ENV_GROUPS 中注册该 key（含描述与是否敏感），最后在各模块用 os.getenv("KEY", default) 读取。
2. 不要硬编码密钥：API Key、Base URL 等一律走环境变量，禁止写死在代码中。
3. 敏感信息不暴露：仅对 sensitive=False 的 key 返回真实值给前端；.env 文件不得提交到版本库（已在 .gitignore 中忽略）。
4. 保持向后兼容：为新增 key 设置合理默认值，避免破坏旧部署。
5. 工作空间文件：如需新增可编辑的 workspace 文件，需在 workspace_service.WORKSPACE_FILES 中注册，并在 ensure_workspace_defaults() 中提供初始内容。
6. 前端变量命名：必须使用 VITE_ 前缀，且仅在确实需要跨域直连后端时才启用。
