PolyStudio 仓库未采用统一的构建编排工具，而是以「前后端各自独立、脚本驱动」的轻量方式组织构建流程。核心特征如下：

1. 后端（Python/FastAPI）
- 依赖管理：`backend/requirements.txt` 固定 FastAPI、Uvicorn、LangChain/LangGraph、Pillow、MoviePy、OpenCV、PyDub 等版本。
- 运行入口：`backend/start.sh` 通过 conda 激活 `polystudio` 环境后，使用 `python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000` 启动服务；同时检查 `.env` 是否存在，并将当前 Python 解释器路径注入 `PYTHON_EXECUTABLE` 环境变量供子进程复用。
- 配置加载：应用通过 `python-dotenv` 读取 `backend/.env`，其中集中声明 LLM 提供商（火山引擎/SiliconFlow）、TTS、3D 生成、ComfyUI、日志级别、Mock 开关等全部运行时参数。
- 辅助脚本：`backend/scripts/normalize_storage_images.py` 用于批量归一化 `/storage/images/` 下的图片格式。

2. 前端（React + Vite + TypeScript）
- 依赖与脚本：`frontend/package.json` 定义 `dev`（vite）、`build`（tsc + vite build）、`preview` 三个 npm script。
- 开发服务器：`frontend/vite.config.ts` 将 `/api` 和 `/storage` 代理到 `http://localhost:8000`，实现前后端联调时统一端口 3000。
- 别名：`@` 指向 `./src`。

3. 缺失的构建能力
- 仓库中不存在 Dockerfile、docker-compose.yml、Makefile、CI 流水线（`.github/workflows`）、发布脚本（release/deploy/build.sh）、包管理元数据（pyproject.toml、setup.py、Pipfile、poetry.lock）等任何容器化或 CI/CD 相关文件。
- 版本信息仅存在于 `frontend/package.json` 的 `version: "1.0.0"`，后端无显式版本声明。

4. 开发者约定
- 新增 Python 依赖需同步更新 `backend/requirements.txt` 并锁定版本。
- 新增前端依赖通过 `npm install` 写入 `package.json` / `package-lock.json`。
- 本地开发顺序：先 `conda activate polystudio && cd backend && ./start.sh`，再在另一个终端 `cd frontend && npm run dev`。
- 所有外部 API Key、模型名、Base URL 等敏感配置必须放在 `backend/.env`，不要硬编码进代码。
